**다시 작업할 때는 이 문서를 먼저 읽는다. 이전 계획과 충돌하면 아래 확정 사항을 우선한다.**

## 이번에 확정한 범위

- 디자인은 마지막 정책서 스크린샷의 밝은 테마를 따른다.
- 도서 검색은 **YES24로 전환**한다. 키는 백엔드에서만 사용한다.
- **홈 화면 위젯은 없앤다.** 최신 링크 정책서에는 위젯 요구가 없었다. 이전 계획의 위젯 연결 항목은 폐기한다.
- **OCR 책 인식은 없앤다.** 표지 촬영·갤러리·이미지 공유 인식과 인식 결과에서 책을 고르는 화면도 모두 제거 대상이다.
- 위젯과 OCR 제거는 아직 코드에 반영하지 않았다. 다음 작업의 첫 순서다.
- 바코드 스캔은 OCR과 별개다. 유지/제거를 별도로 확정하지 않았으므로, 다음 착수 때 확인한다.
- 서가·컬렉션을 이미지로 **내보내서 사진에 저장하는 기능은 유지**한다. OCR용 사진 입력과 혼동하지 않는다.
- 실계정 로그인은 사용자가 나중에 직접 한다. 그전에는 인증된 조회·저장 검증을 요구하거나 시도하지 않는다.

## 다음 작업 순서

1. **위젯 제거**
   - Flutter 위젯 초기화/갱신/진입 코드, `lib/widget_bridge/`, `home_widget` 의존성 제거.
   - Android Glance 코드·리시버·리소스·관련 의존성과 iOS Widget Extension 타깃/임베딩 제거.
   - `home_widget`은 `SharedTokenStore`의 공유 확장 토큰 복사에도 쓰인다. 플러그인만 지워서 공유/인증 코드를 깨뜨리지 않는다. OCR 공유 확장도 없애면 해당 미러와 App Group 사용도 함께 정리한다. 본앱 로그인·토큰 갱신은 유지한다.
2. **OCR와 관련 화면 제거**
   - `lib/features/cover_ocr/`, OCR 결과 라우트, 표지/갤러리 입력 버튼과 샘플 화면·테스트 정리.
   - OCR 전용 `lib/features/share_import/`, Android 이미지 공유 Activity, iOS 이미지 공유 Extension의 필요 없는 구성 제거.
   - `camera`, `google_mlkit_*`, `image_picker` 등은 사용처를 확인한 뒤 미사용 의존성을 제거한다. 바코드 처리 방침을 먼저 확인한다.
   - OCR 의존성이 빠지면 ML Kit 시뮬레이터 우회 스크립트도 필요 여부를 재검토한다. 필요 없으면 제거하고 일반 빌드로 검증한다.
3. **이미지 저장 마무리**
   - 책이 적을 때 이미지 하단의 큰 여백을 줄인다. 현재 출력은 1080×1720 고정이다.
   - 실제 표지·긴 제목·여러 장 저장, 빈 컬렉션, 권한 거부, 중간 실패 후 남은 장만 저장을 확인한다.
   - 불필요 import 안내를 정리하고, 최종 삭제 범위에 맞춰 테스트·정적 분석·iOS/Android 빌드를 확인한다.
4. **문서·검증 결과 갱신**
   - 위젯/OCR를 남은 개발 항목으로 다시 넣지 않는다. Flutter의 화면 테스트를 뜻하는 “위젯 테스트”는 홈 위젯 기능과 별개다.
   - 로그인 또는 YES24 서버가 필요한 작업은 별도 대기 항목으로 남긴다.

## 백엔드와 사용자 대기 항목

- 사용자가 YES24 전환을 백엔드에 요청하기로 했다. [짧은 요청서](../requests/2026-11-04-backend-request-summary.md)를 참고한다.
- 필요한 계약: YES24 제목 검색·ISBN 조회, YES24 상품 ID 저장, 기존 알라딘 책과의 중복 판별, 저장 후 `mybookId` 반환, 최초 기록 정확히 1개 생성 방식.
- 앱의 `YES24_SEARCH_PATH`, `YES24_DETAIL_PATH`는 현재 비어 있다. 서버가 정한 경로/응답이 오면 연결한다. 임의 경로를 추측하거나 앱에 YES24 키를 넣지 않는다.
- 알라딘 오류 999의 실제 메시지는 해당 도메인의 OpenAPI 서비스 종료 안내다. [공식 종료 공지](https://blog.aladin.co.kr/cscenter/17483675)에 기존 이용자 API 종료일이 2026-10-30으로 명시돼 있다. 키 재입력으로 해결할 작업이 아니다.
- 사용자가 로그인한 후 개발 서버의 실제 책/기록 조회, 추가·재조회·재시작·인증 만료를 검증한다. 기존 비인증 GET의 HTTP 500을 인증된 검증 성공으로 간주하지 않는다.
