새 화면을 본앱과 API에 연결했습니다. 서가·독서카드·기록 추가·컬렉션 생성과 편집을 기존 로그인 인증으로 요청합니다. 검색·촬영·갤러리에서 고른 책도 새 화면으로 이어집니다.

밝은 테마를 사용합니다. 자동 테스트 154개와 정적 분석을 통과했고, 본앱 iOS 기기용 빌드도 성공했습니다. 아래 화면 모음은 앞서 별도 프리뷰 앱에서 촬영한 것입니다.

아직 남은 것: 신규 책 저장·정확한 중복 조회, 로그인한 실제 계정으로 저장 검증, 이미지 저장·공유·위젯 연결입니다. API 연결 코드 구현과 실제 서버 검증은 구분해서 진행합니다.

이 순서로 진행합니다

세부 개발 작업을 읽기 쉽게 여섯 단계로 묶었습니다.

  1. 01
    프리뷰 반영 완료

    화면을 정책에 맞추기

    • 컬렉션을 9칸으로 만들고, 빈 칸에서 책을 추가하게 합니다.
    • 책등 두께는 페이지 수에 맞추고, 이유 띠지는 주황색으로 통일합니다.
    • 기록 입력을 내용 한 칸으로 정리하고, 완독 저장은 완료일만 받습니다.
    • 빠진 안내 화면과 날짜 선택 기능을 채웁니다.

    확인할 결과 · 서버 연결 전에도 새 사용 흐름을 직접 눌러볼 수 있습니다.

  2. 02
    연결 구현 · 실계정 검증 대기

    서가에 내 책 불러오기

    • 읽고 싶은 책·읽는 책·읽은 책을 한 서가에 모아 보여줍니다.
    • 전체 권수와 페이지를 맞추고, 책을 열었다 돌아온 위치를 유지합니다.
    • 책이 없을 때, 불러오는 중일 때, 연결에 실패했을 때를 처리합니다.

    확인할 결과 · 로그인하면 샘플 대신 내 책이 보입니다.

  3. 03
    검색·선택 연결 · 신규 저장은 서버 보완 대기

    책 찾고 저장하기

    • 제목 검색·표지/바코드 촬영·갤러리를 새 화면에 연결합니다.
    • 책을 저장하면 선택한 상태와 날짜로 첫 기록을 하나 만듭니다.
    • 이미 있는 책이면 기존 독서카드로 안내합니다.
    • 저장에 실패해도 입력을 유지하고, 재시도로 중복 저장되지 않게 합니다.

    확인할 결과 · 책을 찾아 저장하고, 그 책의 독서카드까지 이동합니다.

  4. 04
    조회·기록 추가 연결 · 실계정 검증 대기

    독서카드에 기록 남기기

    • 카드 앞면에는 현재 상태와 이유, 뒷면에는 날짜 최신순 기록을 보여줍니다.
    • 14가지 카테고리로 기록을 남기고, 자유 기록은 내용을 꼭 입력하게 합니다.
    • 현재 상태는 마지막으로 추가한 상태 기록을 따릅니다. 구매·문장 기록은 상태를 바꾸지 않습니다.
    • 완독 후 과거 날짜의 읽는 중 기록을 추가하면 현재 상태도 읽는 중으로 바뀝니다.

    확인할 결과 · 앱을 껐다 켜도 기록과 카드 상태가 그대로 남습니다.

  5. 05
    생성·편집·기존 책 담기 연결

    컬렉션 완성하기

    • 이름을 정하면 빈 9칸 컬렉션을 만듭니다.
    • 빈 칸에서 책을 찾습니다. 내 서가에 있는 책은 바로 담고, 없는 책은 저장한 뒤 담습니다.
    • 같은 컬렉션의 중복과 9권 초과를 막습니다.
    • 책을 빼면 그 칸만 비웁니다. 원래 서가의 책과 기록은 유지합니다.

    확인할 결과 · 컬렉션을 만들고 책을 담거나 빼도 위치와 기록이 맞게 유지됩니다.

  6. 06
    실제 앱으로 마무리

    기존 기능 연결하고 검증하기

    • 서가와 컬렉션을 이미지로 저장할 수 있게 합니다.
    • 공유로 책 저장, 홈 위젯, 알림에서 열기도 새 화면에 연결합니다.
    • 기존 사용자의 책·이유·날짜가 유지되는지 확인합니다.
    • 아이폰과 안드로이드에서 검증한 뒤 새 화면으로 전환합니다.

    확인할 결과 · 일상에서 사용할 수 있는 앱과 검증 빌드가 준비됩니다.

백엔드 확인 결과

API 문서를 다시 확인했습니다. 전체 서가 조회, 14가지 기록, 컬렉션 9칸과 편집 방식은 문서에 나와 있습니다. 삭제 폴더의 구 기능 다섯 가지는 새 앱에서 사용하지 않는 것으로 계획에 반영했습니다.

아래 네 가지는 문서 설명이 부족해 서버 코드도 참고했습니다. 확인한 코드와 문서가 다른 부분이 있어, 실제 저장을 연결하기 전 담당자 확인이 필요합니다.

책 저장 후 번호 받기 → 보완 필요

문서에 번호 반환 설명이 없고, 확인한 서버 코드도 저장 성공 응답에 책 번호를 넣지 않습니다.

첫 기록 만들기 → 방식 확인 필요

확인한 코드는 책만 저장합니다. 선택한 상태와 날짜로 첫 기록 하나를 만드는 방식은 더 맞춰야 합니다.

중복 책 찾기 → 조회 방식 확인 필요

제목 검색은 있지만 같은 책을 정확히 찾아 기존 번호를 돌려주는 방법은 문서에서 확인되지 않았습니다.

현재 상태 → 기준 결정됨

마지막으로 추가한 상태 기록을 따르기로 정했습니다. 과거 날짜의 읽는 중 기록을 추가해도 읽는 중으로 바뀝니다. 띠지 이유 선택은 별도 규칙으로 확인합니다.

현재 주소가 개발 서버라는 점은 확인됐습니다. 인증 없는 조회는 HTTP 500, 알라딘 검색은 오류 코드 999를 반환했습니다. 로그인한 실제 계정으로 조회·저장 결과를 확인하는 작업은 남아 있습니다. 서가 오류를 샘플 데이터로 대체하거나 제목 검색 오류를 결과 없음으로 숨기지 않습니다.

기존 정책서·테스트와 무엇이 달라지나요?

원본 정책서 4-1은 기록 날짜가 가장 최근인 상태를 따르고, 같은 날짜면 나중에 남긴 기록을 따르도록 되어 있습니다. 이번 합의로 현재 상태는 날짜와 무관하게 마지막으로 추가한 상태 기록을 따릅니다. 목록은 날짜 최신순을 유지합니다. 이번 작업에서 새 상태 규칙과 컬렉션·입력 흐름의 테스트를 추가했습니다. 요청 형식과 인증 연결, 저장 중 대기·실패 시 초안 유지·중복 전송 방지는 자동 테스트로 확인했습니다. 실제 서버에 기록을 저장하는 검증은 남아 있습니다.

삭제 폴더의 다섯 가지는 어떻게 바뀌나요?
  • 직접 책 추가 → 개편 화면에서 제외. 알라딘 책 저장은 유지합니다.
  • 독서 시작 → 읽는 중 기록을 남기는 방식으로 바꿉니다.
  • 책 정보 수정 → 구 편집을 제외하고, 상태와 이유는 기록으로 남깁니다.
  • 히스토리 목록 → 전체 서가와 책별 기록으로 나눕니다.
  • 구 기본서가목록조회 → 새 독서카드 앞면 응답으로 교체합니다.

같은 주소를 새 기능이 쓰는 경우도 있으므로, 주소만 보고 책 저장이나 카드 조회까지 없애지 않습니다.

문서와 코드가 다른 부분도 있나요?

서가 조회 주소와 한 번에 불러올 권수 설정, 일부 응답 항목이 다릅니다. 서버별 설정값을 명시해 연결하도록 구현했습니다. 인증된 응답을 확인한 뒤 최종 설정을 맞춥니다. 사용자가 직접 조사하실 항목은 아닙니다.

완성 여부는 이렇게 확인합니다

  • 저장이 정확하다 — 책과 첫 기록이 중복 없이 남습니다.
  • 기록이 일치한다 — 날짜, 현재 상태, 이유 띠지가 서로 맞습니다.
  • 책이 사라지지 않는다 — 컬렉션에서 빼도 서가와 기록에 남습니다.
  • 실패해도 이어갈 수 있다 — 연결이 끊겨도 입력과 저장된 결과를 보존합니다.
  • 기존 사용도 이어진다 — 내 데이터, 공유 저장, 위젯과 알림이 작동합니다.
이번 작업에 포함하지 않는 것

소셜 기능, 기록 수정·삭제 화면, 컬렉션 삭제, 사용자가 고르는 띠지 색상은 이번 범위에 넣지 않습니다.

검증 전에 필요한 환경 준비

별도 프리뷰 시뮬레이터와 본앱 iOS 기기용 빌드는 성공했습니다. 본앱 시뮬레이터는 기존 플랫폼 설정과 ML Kit 지원 문제로 실행이 막혔습니다. 실계정으로 개발 서버 조회·저장, Android와 iPhone 실기기 검증이 남아 있습니다.

화면 작업에 이어 본앱 경로와 확인된 API 연결을 구현했습니다. 신규 책 저장 계약과 실계정 검증, 이미지 저장·기존 외부 진입점 작업을 이어갑니다.
