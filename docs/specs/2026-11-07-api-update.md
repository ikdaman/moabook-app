# 2026-11-07 API 변경 반영

> **2026-11-08 후속:** 아래의 초기 `limit`/미인증 검증 문구는 이력이다. 앱 기본값은 `size=100`으로 수정했고 인증된 실제 데이터 조회·추가도 진행했다. 최신 상태는 [현재 체크리스트](../plans/2026-11-05-resume-checklist.md)를 따른다.

기준: [Postman 공개 문서](https://documenter.getpostman.com/view/43782154/2sBXcAH2xj)의 최신 공개 컬렉션. 실제 서버의 인증된 조회·저장 검증과는 구분한다.

## 사용자 확인

- 기존 알라딘 책은 모두 제거했다. 알라딘 데이터 이관이나 알라딘/YES24 간 ISBN 중복 판별은 이번 연동에 필요 없다.
- **바코드 스캔은 유지한다.** 추가된 ISBN 상세조회 API를 바코드 인식 후 책 선택 흐름에 연결했다.

## 반영한 계약

- 검색: `GET /books`, `query`, 1부터 시작하는 `page`, `pageSize`(앱은 50). 서버의 `books` 배열을 파싱하며 검색 결과가 없을 때의 `null`도 처리한다.
- 검색 응답의 `aladinId`는 YES24 상품 ID다. 앱 내부에는 YES24 출처로 보관하고 서버 요청에서만 기존 필드명을 사용한다. 쪽수 `totalPages`, 출간일 `PublishDate`를 반영한다.
- 서가: `GET /mybooks`, 0부터 시작하는 `page`, 문서 표의 `limit`. 페이지 크기 키는 환경 설정으로 변경할 수 있다.
- 저장: `POST /mybooks`에 새 `bookInfo`와 선택 `reason`을 전송한다. 예전 `historyInfo`, `source`, ISBN·소개·출간일을 보내지 않는다. 성공 응답의 `mybookId`로 후속 동작을 수행한다.
- 서가 중복: `GET /mybooks/check?aladinId=...`, `mybookId` 또는 `null`.
- 컬렉션 중복: `GET /collections/{id}/books/check?aladinId=...`, `onShelf`, `mybookId`, `alreadyInCollection`.
- 현재 서가/카드의 `aladinId`도 YES24 ID로 해석한다. 응답에 ID가 없으면 추측하지 않으며 검색·저장 중 확인한 출처 정보가 있을 때만 보완한다.
- 새 독서 화면과 온보딩의 로그인 후 보류책 저장에 새 저장 흐름을 적용했다.
- 검색은 서버의 `nowPage`, `totalPages`, `totalElements`를 파싱해 다음 페이지와 전체 권수를 표시한다. 페이지 실패 시 기존 결과를 보존하고 같은 페이지를 재시도하며, 이전 검색의 늦은 응답은 무시한다.

## 첫 기록과 실패 처리

사용자 확인으로 **책 저장과 첫 기록 작성은 분리**한다. 책만 저장한 뒤 빈 독서카드에 `첫 기록 남기기` 버튼을 표시한다. 사용자가 버튼을 눌러 카테고리·날짜·내용을 선택하고 완료할 때만 기록 추가 API를 호출한다. 온보딩의 보류책 저장도 기록을 자동으로 만들지 않는다.

책 저장 화면에는 선택 이유만 남기고 상태·날짜 입력은 기록 작성 화면에서 받는다. 저장한 이유는 기록이 없는 상태에서도 책의 속성으로 유지한다. 컬렉션에 새 책을 담아도 기록을 자동 생성하지 않는다.

앱은 연속 탭을 막고, 책 저장 응답을 놓쳤을 때 중복 확인 API로 기존 `mybookId`를 확인한다. 저장된 책의 카드 조회가 실패하면 같은 책을 다시 만들지 않고 조회를 재시도한다. 사용자가 명시적으로 작성한 기록의 응답이 불확실한 경우에도 기존의 기록 목록 확인 흐름을 유지한다.

서버의 요청 중복 방지 보장은 응답을 놓쳐 같은 저장 요청을 재전송해도 한 번만 저장되게 하는 처리를 뜻한다. 이번 기능의 필수 선행 조건으로 요구하지 않는다. 책 저장과 첫 기록 작성을 한 번에 처리하는 서버 계약도 필요 없다.

## 남은 확인

1. 서가 페이지 크기 설명 `limit`과 예제 이름 `size` 불일치. 앱은 표의 `limit`을 사용한다.
2. 실제 로그인 후 검색·저장·재조회·빈 카드에서 첫 기록 작성 검증. 문서 소개에는 여전히 목업 안내가 있다. 사용자 대신 실계정 인증이나 서버 쓰기를 수행하지 않았다.

## 위젯·OCR 제거와 이미지 마무리

홈 화면 위젯, OCR·갤러리 입력·공유 인식과 관련 네이티브 확장/리시버/의존성을 제거했다. 공유 확장용 토큰 미러만 제거하고 본앱의 로그인·갱신은 유지한다. 카메라와 ML Kit 바코드 의존성은 스캔을 위해 남긴다. `mobile_scanner`는 실제 화면에서 사용하지 않던 중복 의존성이어서 제거했다.

이미지 출력은 1080px 너비와 3열 구성을 유지하며, 실제 행 수에 맞춰 높이를 812/1266/1720px로 조절한다. 빈 내보내기는 저장 대신 안내하고, 부분 저장 시 성공한 장을 제외한 나머지만 재시도한다. 로컬 실제 표지와 긴 텍스트를 넣은 PNG를 생성해 확인했다.

## ISBN 상세조회와 제외한 검증

최신 Postman 명세의 `GET /books/detail?searchType=ISBN13&query={isbn}`을 `searchByIsbn()`에 연결했다. 기본 경로는 `/books/detail`이며 `YES24_DETAIL_PATH`로 변경할 수 있다. 단일 책 객체를 파싱하고 `aladinId`는 YES24 상품 ID로, `totalPages`는 쪽수로, `publishDate`는 출간일로 처리한다. 응답에 ISBN이 없으므로 요청한 ISBN을 보존한다. `null`은 검색 결과 없음으로, 잘못된 객체나 HTTP 200 오류 본문은 실패로 처리한다. ISBN-13 검증과 기존 인증 Dio를 재사용한다. 명세는 `searchType=aladinId`도 지원하지만 이번 스캔 연동은 ISBN13을 사용한다.

사용자 지시로 실계정 검증과 최종 iOS/Android 빌드를 제외했다. Flutter 테스트 160개와 정적 분석은 통과했으며 네이티브 설정은 구조·문법만 확인했다. [전체 작업 상태](../plans/2026-11-05-resume-checklist.md).

ISBN 상세조회 후속 검증: 관련 Flutter 테스트 20개 통과, `flutter analyze --no-pub` 문제 없음. 실제 기기 바코드 인식·서버 응답과 네이티브 빌드는 이번 후속 작업에서도 검증하지 않았다.

## Android 실기기 설치 후속

2026-11-07 사용자 요청으로 Android 빌드·설치를 재개했다. 카메라 플러그인과 충돌한 `WRITE_EXTERNAL_STORAGE`의 `maxSdkVersion`은 앱의 기존 값(29)을 유지하도록 Manifest 병합 규칙을 추가했다. `flutter build apk --debug --dart-define-from-file=env/prod.json` 성공 후 Galaxy A52s(SM-A528N)에 기존 앱을 유지하는 업데이트로 설치했다. 설치 버전은 2.0.21(56)이며 MainActivity 실행과 프로세스 유지를 확인했고, 확인 시점의 오류 로그에는 AndroidRuntime/Flutter 오류가 없었다. 실제 책 바코드 인식→조회→선택·저장 흐름은 아직 확인하지 않았다. iOS 빌드는 수행하지 않았다.

## 2026-11-08 실기기 후속

사용자 요청으로 Android 실기기 검증을 재개했다. 검색은 버튼 대신 무한 스크롤로 변경했고, 큰 글씨의 책등·카드·하단 탭·기록 추가 버튼 배치와 세로 고정을 보완했다. 전체 테스트 169개와 정적 분석 통과. 날짜가 오래된 TODO의 이유 덮어쓰기, 일부 검색어 500, 서가 `limit`/`size` 차이와 설정·내보내기 화면의 디자인 차이를 확인했다. [실기기 검증 결과와 캡처](2026-11-08-android-device-qa.md)를 참조한다.

최종 사용자 선택: 시스템 글자 크기를 변경해도 앱의 각 폰트 크기는 고정한다. 배치 보완과 세로 고정은 유지한다.
