# Android 실기기 검증 — 2026-11-07~08

연결된 Galaxy A52s(SM-A528N), Android 14, 1080×2400, 밀도 450에서 실행했다. 앱은 2.0.21(56) Debug이며 기존 `env/prod.json`의 개발 서버 `https://moabook.shop`을 사용했다. 인증은 사용자 검증을 재사용했다. 기존 서가 2권과 기록은 수정하지 않았으며 별도 테스트 책 10권과 컬렉션으로 검증했다.

## 이번에 수정한 항목

- **무한 스크롤:** 정상 상태의 ‘더 불러오기’를 제거했다. 하단 320dp 이내에서 다음 페이지를 요청하며 동시 요청, 마지막 페이지, 짧은 페이지, 검색어 변경과 늦은 응답을 처리한다. 실패하면 기존 결과와 같은 페이지의 재시도 버튼을 유지한다.
- **앱 글자 크기 고정(최종 사용자 선택):** 시스템 폰트 배율을 앱 전체에서 적용하지 않고 각 화면이 정한 폰트 크기를 유지한다. 키보드 영역과 Safe Area 정보는 보존한다.
- **글자 배치 보완:** 책등 제목은 추가 행간 없이 한 문단으로 세로 배치하고 원문의 띄어쓰기를 유지한다. 첫 글자·마지막 글자의 실제 폰트 높이까지 재서 잘림을 막으며, 공간을 넘는 제목만 말줄임한다. 하단 탭과 기록 추가 버튼 크기를 글씨에 맞추고, 카드의 기록 개수와 추가 동작은 좁으면 줄바꿈한다. 이 배치 보완은 개별 UI 부품에도 남겼으며, 실제 앱은 위의 고정 배율 규칙을 사용한다.
- **세로 고정:** Flutter 시작 설정, Android MainActivity, iOS 방향 설정에 반영했다. iOS는 plist 구조만 확인했으며 실제 빌드·기기 검증 결과는 아니다.

## 남은 문제

### 1. 과거 TODO가 최신 날짜 이유를 덮어씀 — 서버

11/8 TODO `QA_latest_reason`을 저장한 뒤 11/4 TODO `QA_older_reason`을 추가하자 카드 이유가 `QA_older_reason`으로 바뀌었다. 현재 상태를 마지막 추가 기록으로 결정하는 규칙은 정상이나, 이유의 날짜 우선 규칙과는 다르다. 재현 응답 (`output/device-qa/2026-11-07/status-reason-verification.json`).

확인한 [서버 서비스](https://github.com/ikdaman/damda-server/blob/a0f8c174819bd7780feb1efce119e6e3385211c3/src/main/java/com/damda/domain/mybook/service/MyBookServiceImpl.java)는 TODO 추가 시 날짜 비교 없이 `myBook.updateReason(recordReq.getMemo())`를 호출한다. 이유는 TODO 날짜를 기준으로 결정하도록 서버 수정이 필요하다.

### 2. 일부 검색어에서 외부 API 오류 500 — 서버 확인 필요

`GET /books?query=QAzzNoSuchBook938472&page=1&pageSize=50` 및 숫자 임의 검색어에서 HTTP 500, `5000005`가 재현됐다. 앱은 오류와 재시도 화면을 표시했다. 명세의 결과 없음 `200/null` 처리와 외부 API 오류 구분을 확인해야 한다. 외부 서버가 실제로 어떤 상태·본문을 반환했는지는 확인하지 않았다. 응답 (`output/device-qa/2026-11-07/search-negative.json`).

### 3. 설정·사진 저장 화면의 디자인 차이 — 앱

설정은 이전 픽셀 글꼴과 ‘읽고 싶은 책 / 책 추가 / 히스토리’ 하단 메뉴가 남아 있다. ‘히스토리’ 경로는 현재 컬렉션으로 연결되므로 이름도 새 구조에 맞춰야 한다. 사진 저장은 기본 Material 상단바와 보라색 둥근 버튼을 사용한다. 본문 서가의 색·글꼴·직각 버튼과 통일이 필요하다. 설정 (`output/device-qa/2026-11-07/64-settings.png`), 사진 저장 (`output/device-qa/2026-11-07/31-export-one-preview.png`).

### 4. 추가 계약 차이 — 서버·명세

- 서가는 `limit=100`을 무시하고 기본 5권씩 반환한다. `size=100`은 적용된다. 앱은 모든 페이지를 읽으므로 이번 12권 조회에 누락은 없었으나 기본 파라미터를 `size`로 정리할 필요가 있다.
- 같은 날짜 기록의 상대 순서는 안정적이지 않았다. 확인한 서버 정렬은 `recordDate DESC`만 사용한다. 날짜가 같을 때 생성 시각·ID 등 보조 정렬 기준을 확정해야 한다. 현재 상태는 별도 카드 응답을 사용하므로 이 순서에서 추측하지 않는다.

## 정리와 검증 범위

테스트 책 354~363은 서가에서 제거했다. 기존 두 책과 이유·기록은 검증 시작 전 응답과 동일함을 비교했다. 컬렉션 삭제 API가 없어 **`QA_1108_device`(ID 1) 한 개를 빈 상태로 남겼다.** 테스트로 저장한 사진 5장은 기기에서 정리하고 원본 PNG는 아래 산출물 폴더에 보관했다. 데이터 정리 결과 (`output/device-qa/2026-11-07/cleanup-verification.json`).

폰트 배율 1.1, 자동 회전·사용자 회전 값, Wi-Fi·모바일 데이터, 카메라 권한은 원래 상태로 복구했다. 앱은 새 세로 고정 설정을 유지한다.

인증·계정 전환, 푸시 실제 수신, iOS 빌드·기기 검증은 이번 범위에서 제외했다. 실제 책을 카메라 앞에 제시하는 물리적 바코드 인식은 앞선 사용자 성공 확인을 재사용했으며, 이번 자동 조작에서는 카메라·권한·토치·복귀까지만 새로 확인했다. 저장 공간 부족·사진 저장 중간 실패·응답 유실·다른 기기와의 동시 수정은 실기기에서 강제 재현하지 않았으며 기존 주입 테스트와 구분한다.

계정 정보가 포함될 수 있는 캡처와 실서버 응답 원본은 공개 저장소에서 제외하고 로컬에만 보관한다. 산출물은 산출물 폴더 (`output/device-qa/2026-11-07/`)에 있다. 이 폴더에는 인증 토큰을 저장하지 않았다.

## 11/8 후속 — 예시 서가 데이터와 표지 캐시

- 사용자 요청으로 연결된 기기의 로그인 계정에 실제 검색 도서 72권, 예시 기록 295개, 주제 컬렉션 8개(각 9권)를 추가했다. 기존 4권과 기록은 저장 전후 응답을 비교해 변경 없음을 확인했다. 전체 76권은 연결 기기 너비의 책등 배치 계산상 9줄·3페이지다.
- 기록은 14종 카테고리와 서로 다른 날짜·분량을 포함한다. 기록이 없는 책, 기록이 1개인 책과 26개인 책을 함께 준비했다. 문장 카테고리의 내용도 예시 감상이며 실제 책의 인용문으로 작성하지 않았다.
- 컬렉션 목록은 기존처럼 슬롯 순서의 첫 두 권을 대표 표지로 사용한다. 공통 표지를 `CachedNetworkImage`로 변경해 최초 다운로드 후 기기의 디스크 캐시를 재사용한다. 표지가 없거나 다운로드에 실패하면 기존 회색 대체 영역을 표시한다.
- 관련 기록·컬렉션 흐름 테스트 28개 통과, 변경한 UI 파일 정적 분석 문제 없음. 생성 데이터 목록과 원본 보존 비교 자료는 `output/device-qa/2026-11-08/seed-library/`에 로컬 보관한다. 인증 토큰은 이 산출물에 저장하지 않았다.

### 서가 탭 전환 갱신

기본 서가 탭을 누르면 책 목록을, 주제 서가 탭을 누르면 컬렉션 목록과 현재 컬렉션 상세를 다시 조회한다. 같은 탭을 다시 눌러도 갱신하며 해당 목록 조회가 진행 중이면 중복 호출하지 않는다. 앱 첫 진입·포그라운드 복귀·저장 후의 기존 갱신도 유지한다. 탭 전환 후 서버에서 바뀐 책과 컬렉션이 반영되고, 이전에 불러온 컬렉션 상세도 다시 조회되는 회귀 테스트를 추가했다.

### 기본 서가 스와이프와 배경 갱신

- 기본 서가의 페이지 변경은 API를 호출하지 않는다. 전체 Workspace의 `setState` 대신 페이지 번호만 `ValueNotifier`로 갱신하고 인접 페이지를 미리 준비한다. 책마다 반복하던 전체 ID 목록 생성·탐색은 페이지 구성 시 만든 인덱스 맵을 사용한다.
- 책등 제목의 말줄임은 모든 접두사를 차례로 측정하던 방식에서 이진 탐색으로 바꿨다. 서체 높이·띄어쓰기·말줄임 크기 및 페이지 넘김 회귀를 포함한 테스트 30개 통과.
- 책·컬렉션 목록은 첫 조회 성공 이후 메모리 캐시를 보여두고 배경에서 갱신한다. 컬렉션 목록을 갱신해도 기존 슬롯과 이미 로드한 상세는 유지하며, 오래된 상세는 방문 시 다시 조회한다. 지연된 서버 응답 중에도 캐시 화면이 유지되는 회귀 테스트를 추가했다.
- 실제 서버는 `limit=100` 대신 `size=100`을 인식하므로 앱 환경의 기본 페이지 크기 키를 `size`로 수정했다. 기존 설정에서는 전체 76권을 5권씩 16번 조회해야 했으며 이제 현재 서가는 1회 응답에 들어간다. 환경·원격 데이터소스·기록 흐름 테스트 36개 통과.
- 성능 확인용 Profile APK를 빌드했다. 자동화 도구에서 기기 미러링 앱에 접근하지 못해 실제 스와이프 프레임 시간과 수정 전후 수치 비교는 확보하지 못했다. 테스트 통과는 실기기에서 끊김이 완전히 사라졌다는 측정 결과를 뜻하지 않는다.

### 서가 경계 스와이프와 컬렉션 역순

- 기본 서가 마지막 페이지에서 왼쪽으로 밀면 주제 서가 첫 컬렉션으로 이동한다. 첫 컬렉션에서 오른쪽으로 밀면 기본 서가 마지막 페이지로 돌아간다. 경계에서 시작한 드래그의 초과 이동이 48dp 이상일 때 전환하고, 내부 페이지 이동이나 짧은 드래그로는 탭을 전환하지 않는다.
- 두 영역은 280ms 슬라이드로 전환한다. 애니메이션 완료 후 대상 목록과 필요한 컬렉션 상세를 조회하며, 캐시가 있으면 계속 표시한다. 전환 중 입력은 중복 전환을 막기 위해 차단한다.
- 서버 컬렉션 목록을 역순으로 표시한다. 새 컬렉션 생성 직후와 상세 재조회가 필요한 생성 부분 성공 상태도 목록 맨 앞에 둔다.
- 전체 테스트 182개 통과, 전체 정적 분석 문제 없음. 경계 왕복·마지막 페이지 복원·일반 컬렉션 넘김·전환 중 조회 없음·완료 후 갱신·역순 표시를 자동 테스트로 확인했다. 기기에서 실제 드래그의 프레임 수치는 측정하지 않았다.

- `Dio`의 요청·응답 전체 로거를 제거했다. 인증 헤더뿐 아니라 요청/응답 본문도 출력하지 않는다. FCM 원문 토큰과 메시지 본문 출력도 제거했다. 토큰 갱신 서버와 앱 복귀 갱신 담당도 확인해 새 UI의 중복 복귀 조회를 제거했다.

- Android 성능 측정(동일 시나리오, 전후 각 140프레임): 방문한 서가 페이지 유지와 직각 책등의 불필요한 안티앨리어싱 클립 제거 후 UI 구성 평균 11.122ms→4.042ms, P99 138.140ms→69.174ms, 구성 예산 초과 12→3프레임. 평균 GPU 그리기는 15.823ms→15.744ms로 큰 변화가 없으며 일부 지연이 남는다. 모든 기기·실계정의 매끄러움을 보장하는 수치가 아니다. `android-profile-library.json`, `android-profile-library-improved.json`에 원본을 로컬 보관한다.
- 실계정 Android 통합 검증은 `flutter drive`의 기본 종료 처리에서 앱이 제거돼 로컬 로그인 정보가 초기화되면서 완료하지 못했다. 보안 저장소 마이그레이션 로그보다 근본 원인은 도구의 앱 제거 동작이며, 이후 기기 테스트에는 `--keep-app-running`을 명시한다. 서버 기록을 수정하는 테스트로 진행하지 않았다. 실제 소셜 로그인·다른 계정 전환은 사용자의 재로그인이 필요하며 자동 모의 응답 검증과 별개다.
- 서버 세 항목은 [후속 요청 문서](../requests/2026-11-08-server-followups.md)에 재현·기대 동작·종료 조건을 정리했다. 이 문서 앞부분의 설정/내보내기 디자인과 `limit`/`size`는 이번 앱 변경으로 해결됐으며 서버 미해결 세 항목과 구분한다.

### 로그인·회원가입 후속 디자인

로그인·회원가입도 서가와 같은 밝은 팔레트·Plex/Gowun 서체·직각 입력창과 버튼으로 맞췄다. 소셜 SDK 연결·약관 링크·Apple 표준 로그인 버튼은 유지한다. 짧은 화면의 로그인 스크롤, 로딩 중 중복 탭 차단, 키보드 위 회원가입 완료 버튼, 10자 닉네임과 중복 안내·수정 후 재시도를 검증했다. 로그인으로 돌아갈 라우트 스택이 없어도 기본 로그인 경로로 이동한다. Android/iOS 로그인 화면과 회원가입의 로컬 렌더링도 확인했다.

## 튜토리얼과 첫 기록 디자인 후속

튜토리얼의 픽셀 책·네이비·픽셀 팝업·반복 폭죽을 먹색 서문, 명조체 타이핑, 종이색 검색·입력 시트, 첫 책의 1회 선반 도착 연출로 교체했다. 입력 시트에서 선택한 표지·제목·저자를 유지하고 선택 이유는 400 grapheme까지 받는다. 키보드가 올라오면 검색 질문을 간결하게 줄이고, 이유 입력 본문만 스크롤해 선택 버튼을 유지한다. 본앱 기록 종류/작성 시트에도 표지·제목·저자를 보여준다. 로그인 전에는 선택·메모만 보관하며 실제 기록을 자동 생성하지 않는다.

검색→책 선택→이유→로그인 전달, 오류 재시도, 검색·추가 페이지의 늦은 응답, 이모지 400자, 로그인에서 튜토리얼 재진입을 포함해 전체 테스트 196개가 통과했다. 시각 확인 캡처는 `output/device-qa/2026-11-08/tutorial/`에 로컬 보관한다. [설계·정책·검증 범위](2026-11-08-onboarding-redesign.md).
