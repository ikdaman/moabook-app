# 독서 기록·검색 API 후속 확인 요청

작성일: 2026-11-08. 아래는 11월 7~8일 실기기 검증에서 관찰한 세 항목이다. 서버 수정이나 수정 배포 후 재검증은 아직 하지 않았다. 이 문서는 요청사항 정리이며 외부 전송은 하지 않았다.

## 1. 과거 TODO 기록 추가 시 띠지 이유가 덮어써짐

- 대상: `POST /mybooks/{mybookId}/records`, `GET /mybooks/{mybookId}`.
- 재현: 11월 8일 TODO에 `QA_latest_reason`을 기록한 뒤, 11월 4일 TODO에 `QA_older_reason`을 추가한다.
- 관찰: 카드의 `reason`이 `QA_older_reason`으로 바뀐다.
- 기대: 띠지는 기록 날짜가 가장 최근인 TODO의 내용을 사용하므로 `QA_latest_reason`을 유지해야 한다. 같은 날짜라면 나중에 생성한 기록을 선택한다.
- 현재 독서 상태는 이 규칙과 다르다. TODO/INPROGRESS/DONE 중 **마지막으로 추가한 기록**을 따르므로 과거 날짜의 상태 기록이 현재 상태를 바꾸는 것은 허용한다.
- 확인 요청: TODO 생성 시 날짜·생성 순서를 비교해 이유를 계산하고, 최신 TODO의 내용이 비어 있으면 띠지를 제거하는 규칙도 유지해 달라.
- 검증 기준: 최신 날짜→과거 날짜, 과거 날짜→최신 날짜, 같은 날짜, 빈 내용, DONE/INPROGRESS 추가 후 이유 유지.
- 기존 재현 자료: `output/device-qa/2026-11-07/status-reason-verification.json` (로컬 전용).

## 2. 일부 검색어의 결과 없음과 서버 오류 구분

- 대상: `GET /books?query=QAzzNoSuchBook938472&page=1&pageSize=50` 및 임의 숫자 검색어.
- 관찰: HTTP 500, 오류 코드 `5000005`가 반환됐다. 앱은 검색 실패·재시도를 표시한다.
- 기대: 정상적으로 검색했으나 일치 도서가 없는 경우에는 정상 응답으로 결과 없음을 표현한다. 외부 YES24 요청 자체가 실패한 경우에는 서버 장애로 구분해야 한다.
- 확인 요청: 위 검색어의 외부 응답을 확인해 빈 검색 결과 파싱 실패인지, 실제 외부 API 장애인지 분리해 달라. 외부 응답의 상태·본문은 앱에서 확인하지 못했다.
- 검증 기준: 일반 검색어·일치 결과 없는 검색어·숫자 검색어·특수문자·외부 API 실패를 각각 확인하고, 정상 응답은 현재 페이지/전체 건수와 모순되지 않아야 한다.
- 기존 재현 자료: `output/device-qa/2026-11-07/search-negative.json` (로컬 전용).

## 3. 같은 날짜 기록 목록의 안정적인 정렬

- 대상: `GET /mybooks/{mybookId}/records`.
- 관찰: 같은 날짜 기록 사이의 상대 순서가 안정적이지 않았다. 검토 당시 정렬은 `recordDate DESC`만 적용돼 있었다.
- 확인 요청: `recordDate DESC` 뒤에 생성 시각 DESC, 최종적으로 고유 ID DESC 등 일관된 동률 정렬 기준을 명시하고 서버에서 적용해 달라. 생성 시각·ID 필드의 실제 명칭과 보장 범위도 함께 알려 달라.
- 검증 기준: 같은 날짜에 서로 다른 종류의 기록을 3개 이상 생성하고 반복 조회·앱 재시작 후에도 같은 순서를 반환한다. 날짜가 다른 기록은 최신 날짜부터 나온다.
- 현재 독서 상태는 카드 응답을 사용하며, 앱이 기록 목록의 첫 항목에서 상태를 추측하지 않는다.

## 범위와 완료 조건

이 세 항목은 서버 배포 후 인증된 테스트 계정에서 재현·기대 결과를 비교해 종료한다. 사용자의 기존 기록을 수정하는 방식으로 재검증하지 않는다. 서가의 페이지 크기 키 `limit`/`size` 차이는 앱 기본값을 `size`로 바꿔 해결했으며 이번 미해결 목록에서 제외한다.
