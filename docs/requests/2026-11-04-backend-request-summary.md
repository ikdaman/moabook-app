# 모아북 개편 — 백엔드 요청 요약

> **2026-11-07 후속:** 검색·저장 ID·중복 확인 API는 추가돼 앱에 반영했다. 바코드 스캔은 유지하며 추가된 ISBN 상세조회 API(`/books/detail`)도 앱에 연결했다. 최초 기록은 책 저장과 분리해 빈 카드의 버튼으로 작성하므로 자동 생성 계약은 요청하지 않는다. 아래는 이전 요청의 이력이다. [현재 상태](../specs/2026-11-07-api-update.md).


2026-11-05 갱신 · **YES24 전환 기준.** 위젯과 OCR 기반 책 인식은 폐기하며 관련 API는 요청하지 않습니다.

## 1. YES24 도서 검색·ISBN 조회

앱이 호출할 백엔드 경로와 요청/응답 명세를 정해주세요. YES24 API 키는 서버에만 보관합니다.

- 제목/저자 검색: 검색어, 페이지, 페이지 크기. 앱은 목록에서 책을 선택합니다.
- ISBN13 조회: 바코드 유지 시 필요합니다. 바코드 기능의 유지 여부는 별도 확정 예정입니다.
- 필요한 정보: YES24 상품 ID, ISBN13, 제목, 저자, 출판사, 표지, 출간일, 페이지 수, YES24 상품 링크.
- [공식 검색 문서](https://developers.yes24.com/api-doc/goods-item-list), [상세/ISBN 문서](https://developers.yes24.com/api-doc/goods-item-detail), [서버 경유 안내](https://developers.yes24.com/support/faq).
- 앱에는 공식 응답 형태의 파서를 준비했습니다. 백엔드에서 응답을 가공하면 최종 형태를 알려주세요.

## 2. 책 저장 후 내 책 ID 반환

책 저장 성공 응답에 `mybookId`를 반환해주세요. 카드 열기·기록 추가·컬렉션 연결에 필요합니다.

- 확인한 기존 `POST /mybooks` 컨트롤러는 서비스 결과를 버리고 본문 없는 201을 반환했습니다.
- YES24 출처와 상품 ID를 보내는 필드도 확정해주세요. YES24 ID를 기존 `aladinId`에 넣지 않습니다.
- 서가/카드/컬렉션 조회에도 출처·외부 ID·ISBN을 포함할 수 있는지 확인해주세요.

## 3. 기존 책 중복 확인

로그인한 사용자의 서가에 같은 책이 있는지, 있다면 기존 `mybookId`를 돌려줄 방법이 필요합니다.

- 신규 책은 YES24 ID를 사용합니다. 기존 알라딘 책과의 동일 판본 식별은 ISBN13 등으로 기준을 정해주세요.
- 제목/저자 키워드 검색을 정확한 중복 판정으로 사용하지 않습니다.
- 저장 시에도 중복을 방지하고 기존 ID를 반환해주세요. 컬렉션에는 같은 책을 여러 컬렉션에 담을 수 있습니다.

## 4. 최초 기록과 나머지 명세

- 책 저장 후 반환된 ID로 기존 기록 추가 API를 호출해 최초 상태·날짜의 기록을 정확히 1개 만드는 방식인지 확인해주세요. 부분 성공·재시도 시 중복 방지 방법도 필요합니다.
- 현재 상태는 날짜와 무관하게 마지막으로 추가한 TODO/INPROGRESS/DONE 기록을 따릅니다. 구매·문장 등은 상태를 바꾸지 않습니다. 목록은 날짜 최신순입니다.
- 개발 서버의 실제 서가 경로(`/mybooks` 또는 `/mybooks/store`), 페이지 인자(`size` 또는 `limit`), ID 필드명과 기록 ID 반환 여부를 확정해주세요.
- 삭제 폴더의 구 API 다섯 항목은 개편 화면에서 사용하지 않습니다.
