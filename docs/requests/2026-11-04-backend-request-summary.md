# 모아북 개편 — 백엔드 요청 요약

2026-11-04 · API 문서 및 서버 main 코드 검토 기준. 실제 배포 버전과 차이가 있으면 알려주세요.

## 1. 책 저장 응답에 내 책 ID 반환

`POST /mybooks` 성공 응답에 `mybookId`를 반환해주세요.

- 확인한 코드에서는 서비스가 만든 결과를 컨트롤러가 응답에 넣지 않아 본문 없는 201을 반환합니다.
- 저장 직후 독서카드 열기, 기록 추가, 컬렉션 연결에 필요합니다.
- 응답 예: `{ "mybookId": 123 }`

## 2. 알라딘 ID로 내 서가의 중복 책 확인

로그인한 사용자의 서가에 해당 `aladinId`가 있는지와, 있다면 기존 `mybookId`를 조회할 수 있게 해주세요. 신규 API 또는 기존 조회 API 확장 모두 가능합니다.

- 서가에 다시 저장할 때는 기존 카드로 안내합니다.
- 컬렉션에 담을 때는 이미 서가에 있는 책이면 저장 시트를 생략하고 바로 연결합니다.
- 사전 조회 이후에도 중복 저장이 생기지 않도록 저장 API에서도 중복을 막고 기존 ID를 반환해주세요.
- 같은 컬렉션의 중복은 기존 책 ID와 컬렉션 목록으로 앱에서도 확인할 수 있습니다.

## 3. 최초 기록 생성 흐름 확인

책 저장 후 반환받은 `mybookId`로 기존 `POST /mybooks/{mybookId}/records`를 호출하는 방식으로 진행해도 되는지 확인 부탁드립니다.

- 최초 선택 상태(TODO/INPROGRESS/DONE)와 날짜로 기록이 정확히 1개 남아야 합니다.
- 책 저장 시 서버가 기록을 자동 생성하는지, 기록 추가 실패·재시도 시 중복을 방지할 방법이 있는지 알려주세요.

## 정책 및 명세 확인

- **현재 상태는 날짜와 무관하게 마지막으로 추가한 상태 기록을 따르기로 변경했습니다.** 완독 후 과거 날짜의 INPROGRESS를 추가하면 읽는 중으로 바뀝니다. 날짜 우선 상태 재계산은 요청하지 않습니다. 기록 목록은 날짜 최신순을 유지합니다.
- 실제 서버 주소, 서가 조회 경로(`/mybooks` 또는 `/mybooks/store`), 페이지 인자(`size` 또는 `limit`)와 응답 예제를 확정해주세요. 앞면의 내 책 ID 필드명과 기록 목록의 `recordId` 포함 여부도 문서와 코드가 달라 확인이 필요합니다.
- 문서의 삭제 폴더에 있는 다섯 구 기능은 개편 앱에서 사용하지 않을 예정입니다.
